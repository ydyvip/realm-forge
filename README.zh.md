# 万象工坊

一个纯前端（HTML + CSS + 原生 JS，无框架、无构建依赖）的沙盒世界 / 角色 / 战斗推演 / 远征系统。

English version: [README.md](./README.md)。

## 直接使用

`realm-forge.html` 是已经打包好的单文件版本，双击或用浏览器直接打开即可运行，不需要任何构建步骤。所有数据保存在浏览器的 `localStorage` 里（键名前缀 `realmforge:v1:`）。

应用默认是中文；右上角的语言切换按钮可以随时切到英文。界面外壳与所有「新生成」的内容（角色、世界、势力、地图、远征）都会用当前语言生成。切换语言之前已经生成的内容会保留生成时的语言——就像切换一个应用的显示语言，不会让角色的名字跟着改名一样。

## 这是什么

八层结构，上一层的输出是下一层的输入：

1. **法则层**——八个旋钮（重力、时间流速、空间稳定度、熵律、灵能浓度、异常浓度、因果刚性、心念显化）定义世界的规则，并推导出「违常指数」。
2. **空间层**——程序化生成的地点与路线地图，每个地点在世界旋钮之上叠加局部偏移。
3. **体系层**——魔法、异常、超能力、权能四套互相克制的能力逻辑，各自有明确的力量来源、代价、限制与失控方式。
4. **能力层**——由 18 个可解锁的域 × 10 种效果 × 形态/触发/代价组合生成。
5. **角色层**——15 种出身、按位阶预算分配的六维属性、五维性格，以及会体现角色能力的外观细节。
6. **社会层**——带有理念与外交关系的势力，会自行宣战、媾和、扩张、衰落；一张连接角色与势力的关系网。
7. **成长层**——角色获得经验、按经历权重分配属性成长、能力随之进化，并留下永久的伤痕与经历。
8. **推演层**——回合制战斗引擎（单挑到 5v5 小队）配合蒙特卡洛胜率估算，以及一个持续运作的远征模式：队伍在地图上行军、触发遭遇，并被卷入随时间持续改变世界格局的势力战争。

## 源码结构（`src/` 目录）

```
src/
├─ logic.js         纯逻辑层：世界法则、四大体系、能力生成、角色生成、
│                    推演引擎（单挑/小队）、势力与关系、地图生成、
│                    成长系统、远征引擎（行军/遭遇/战争/领土）。不依赖
│                    DOM，可以直接在 Node 里 require 测试。
├─ i18n_strings.js   静态界面外壳（导航、标题、按钮、说明文字）的中英
│                    对照词典，以及应用这套词典的 i18n 引擎。
├─ ui.js             界面层①：SVG 绘制辅助（量规/雷达图/印记/克制三角/
│                    时间线）、世界与角色工坊的渲染与交互、顶部导航。
├─ ui2.js            界面层②：地图编辑、势力编辑、关系网可视化、
│                    单挑与小队推演的界面。
├─ ui3.js            界面层③：角色成长展示、远征标签页的完整界面
│                    （组队、行军、遭遇选项、战报、天下大势、纪事）。
├─ main.js           入口，调用 init()。
├─ body.html          页面骨架（各标签页的 DOM 结构），用 data-i18n
│                    属性标记可翻译的文字。
└─ style.css         样式（制图纸风格，含浅色/深色主题）。
```

`logic.js` → `i18n_strings.js` → `ui.js` → `ui2.js` → `ui3.js` → `main.js` 依次拼接成同一个 `<script>` 标签，彼此之间通过全局函数（`function` 声明会在整个拼接后的脚本里被整体提升）直接调用，没有模块系统，所以文件顺序不能打乱。

## 重新构建

```bash
python3 build.py
```

会读取 `src/` 下的上述文件，输出到 `realm-forge.html`。改了 `src/` 里任何一个文件后，重新运行这条命令即可看到效果。（脚本默认写到 `/mnt/user-data/outputs/realm-forge.html`；如果在别的环境运行，改一下 `build.py` 末尾的输出路径即可。）

## 翻译是怎么做的

大部分中英文内容直接写在 `logic.js` 的数据表里，单个值用 `{ zh: '...', en: '...' }` 的形式，随机选取用的数组则用等长的 `{ zh: [...], en: [...] }` 词库（等长是为了让同一个随机种子在两种语言下取到相同下标——结果确定、也不影响数值平衡）。三个小工具函数——`tf()`（翻译字段）、`tb()`（翻译词库）、`T(zh, en)`（就地二选一）——在渲染或生成的那一刻，按当前语言解析出对应文本。结构性的参考数据（体系名称、出身特质、能力域名称、地点类型等）是实时查找的，所以切换语言会连带重新标注已经存在的角色和世界；而程序化生成的「风味文本」（角色姓名、技能名、背景故事、纪事条目）则是在生成那一刻的语言写死的，不会随后续切换语言而改变——这是有意为之的设计。
